**Goal:** Admin tự thêm, xem trước và bật một ngôn ngữ mà không cần deploy, trong giới hạn `SCRIPT_FONTS` (spec §8). Web khách có URL, nút chuyển ngôn ngữ, hreflang và sitemap theo ngôn ngữ. Mọi form nội dung có tab ngôn ngữ, có trạng thái "Máy dịch / Đã duyệt / EN đã đổi" và có hàng chờ duyệt. Email gửi khách bằng ngôn ngữ khách dùng khi đặt bàn.

Nghiệm thu theo spec §14.1, dòng 8:
- Thêm `ko` không cần deploy.
- `/vi` hiện bản đã duyệt, và lấy EN cho chỗ thiếu.

**Architecture:**
- **Đường đọc hiện có giữ nguyên.** Các reader nội dung đã nhận `locale` và tự lùi về ngôn ngữ mặc định theo từng trường (`lib/server/content/sql.ts`: `LOCALE_CTE`, `i18nJoin`, `tr`, `mediaJson`). `loadStringRows` và `resolveStrings` đã làm điều tương tự cho chuỗi. Đợt 8 không viết lại đường đọc, chỉ sửa:
  - **Proxy:** đọc ngôn ngữ đang bật từ DB, best effort (C2).
  - **Root layout:** gắn font theo chữ viết (C3).
  - **Layout `(guarded)`:**
    - cấp danh sách ngôn ngữ cho nút chuyển (C4);
    - thêm `alternates` (C5);
    - mở được ngôn ngữ đang tắt khi ở Draft Mode (C6).
  - **Các lỗi lùi ngôn ngữ còn sót:** L8-1, L8-2 và L8-3 (C11).
- **Hai thứ thêm vào DB, đều trong migration 010 (C1):**
  - **Tính hợp lệ của mã ngôn ngữ:**
    - `locales.script` phải là một khóa của `SCRIPT_FONTS`;
    - xóa một ngôn ngữ khi `social_links.visible_locales` còn trỏ tới nó thì bị trigger từ chối (L8-6).
  - **Chính sách theo ngôn ngữ (T8.3, SEC-3):**
    - `legal_versions` có thêm cột `locale`;
    - `reservations` có thêm cột `consent_locale`.

  Không thêm bảng mới. Trạng thái "EN đã đổi" không lưu thành cột riêng: nó được suy ra từ `source_hash` khác hash hiện tại của hàng ngôn ngữ mặc định (C8).
- **Ghi bản dịch (C8, C9):** một lần lưu ở form admin ghi đúng ngôn ngữ của tab đó. Hàng được ghi với `status='reviewed'`, `origin='human'`, và `source_hash` bằng hash các trường của hàng mặc định tại lúc lưu (`lib/i18n/source-hash.ts`). Lưu hàng mặc định thì không đụng tới hàng khác, nên các hàng khác tự thành "EN đã đổi".
  - Form đã gửi `<field>.<locale>` từ 7A. Factory (`makeListEditor`, `writeTranslations`) đã ghi theo các ngôn ngữ được gửi lên. Phần đổi là:
    - zod (`translatable`);
    - các hàm `*Values()`;
    - các truy vấn danh sách đang cứng `'en'`;
    - prop `locales` của `TranslatableField`.
- **Chuỗi (C9):** `strings-admin.ts` bỏ hằng `LOCALE = 'en'` và nhận `locale` cho mỗi lần đọc và ghi. Mỗi màn chuỗi có bộ chọn ngôn ngữ (`?lang=vi`).
  - Server từ chối bản dịch có biến hoặc cấu trúc ICU khác bản EN (spec §7.4). Phép so dùng `messageArgs`, sẵn có trong `lib/i18n/icu.ts`.
  - Email và chính sách sửa được theo ngôn ngữ. Lưu chữ chính sách ở ngôn ngữ X tạo một phiên bản chính sách cho X.
- **Quản lý ngôn ngữ (C7):** màn `/admin/locales`, chỉ Admin (`locales:update` đã có trong `permissions.ts`).
  - Thêm từ danh mục trong code (`lib/i18n/catalog.ts`). Ngôn ngữ mới thêm ở trạng thái tắt.
  - Bật hoặc tắt, có cổng chặn khi bật (R10, R8-6).
  - Bật hoặc tắt `serve_machine`.
  - Sắp thứ tự.
  - Xóa, với các điều kiện từ chối (L8-6).
  - Sửa "link mạng xã hội hiện ở ngôn ngữ nào" (R39).
  - Mỗi thay đổi làm mới tag `locales` và `i18n:<code>` của ngôn ngữ bị đổi, qua `tagsForLocales()`.
- **Xem trước (C6):**
  - `GET /api/admin/preview?path=/ko/...` kiểm quyền, bật Draft Mode, rồi chuyển tới trang. `GET /api/admin/preview/exit` tắt Draft Mode.
  - Ở Draft Mode, `requireEnabledLocale` chấp nhận mọi ngôn ngữ có trong bảng, và trang có `noindex`.
  - Mọi hàm `'use cache'` chạy lại ở mỗi request, nên không phải sửa reader nào (docs `use-cache.md:265-287`, `draft-mode.md`).
- **SEO (C5):**
  - `metadataBase` lấy từ `siteOrigin()`. Thứ tự: `SITE_URL`, rồi `https://` + `VERCEL_PROJECT_PRODUCTION_URL`, rồi `http://localhost:3000`.
  - `alternates`: `canonical` và `languages`, gồm mọi ngôn ngữ đang bật cộng `x-default` trỏ về ngôn ngữ mặc định.
  - `app/sitemap.ts` có `alternates.languages`. `app/robots.ts` chặn `/admin` và `/api`, và trỏ tới sitemap.
- **Độ phủ và duyệt (C10):** màn `/admin/translations` gồm hai phần.
  - **Độ phủ:** theo từng ngôn ngữ và từng loại nội dung, đếm thiếu, máy dịch, đã duyệt và EN đã đổi.
  - **Hàng chờ duyệt:** gồm bản máy dịch, alt EN do máy viết và bản EN đã đổi. Mỗi mục có ba nút "Duyệt", "Vẫn đúng" (ghi lại `source_hash`) và "Sửa". Nút "Dịch tất cả phần còn thiếu bằng AI" và job dịch hàng loạt là **đợt 9**: ở đợt 8 nút hiện ở trạng thái tắt, kèm ghi chú.

## Rulings

Các quyết định dưới đây do plan chốt, dựa trên spec, ledger và research đã dẫn. Mục nào đánh dấu **(chủ dự án)** thì cần owner xác nhận trước khi task tương ứng bắt đầu; nếu chưa có câu trả lời, giá trị trong ngoặc vuông là mặc định.

- **R8-1. Mã ngôn ngữ không đổi được sau khi tạo.** Ngôn ngữ chỉ được thêm từ danh mục, nên không có thao tác đổi tên. Vì vậy không cần viết lại `visible_locales` khi đổi mã (rủi ro 8 của đợt 6 đóng). `ON UPDATE CASCADE` của các FK giữ nguyên, phòng khi sửa tay trong DB.
- **R8-2. Xóa một ngôn ngữ:**
  - **Từ chối khi:**
    - ngôn ngữ đó là mặc định;
    - ngôn ngữ đó đang bật;
    - có `reservations`, `email_outbox` hoặc `notification_recipients` trỏ tới nó (các FK này là NO ACTION);
    - có `legal_versions` hoặc `reservations.consent_locale` trỏ tới nó;
    - có `social_links.visible_locales` chứa mã đó. Trigger của C1 từ chối; màn liên hệ hoặc màn ngôn ngữ phải sửa link trước.
  - **Khi được phép:** các hàng `*_i18n` và `content_strings` của ngôn ngữ đó bị xóa theo (CASCADE). Màn hỏi xác nhận và ghi rõ số hàng sẽ mất.
- **R8-3. Font CJK (chủ dự án / dev).**
  - **[A] `next/font/google`** cho riêng Noto Sans KR/SC/JP, với `preload: false`, chỉ hai trọng lượng 400 và 500.
    - Build (Vercel và CI GitHub) tải font về và tự phục vụ từ cùng origin, nên trình duyệt không gọi bên thứ ba.
    - Font Latin và Việt vẫn dùng `next/font/local` như cũ.
    - Lý do: Google chia mỗi font CJK thành khoảng 100 lát `unicode-range`. Tự host sẽ phải commit hàng trăm file woff2, khoảng 30 MB.
  - **[B] Tự host qua `scripts/fetch-cjk-fonts.mjs`**, chép các lát woff2 vào `lib/fonts/cjk/`. Chỉ chọn nếu build không được ra mạng.

  `check-prerender.mjs` (C3) kiểm rằng trang EN không link tới font CJK nào.
- **R8-4. Khóa phiên bản (token) của một item vẫn tính trên mọi ngôn ngữ (giữ R2 của 7A).** Form hiện tab của mọi ngôn ngữ có trong bảng, nên một lần lưu bản VI của đồng nghiệp đúng là một thay đổi trên form đang mở. "Tải lại" giữ chữ đã gõ, như 7A. Không làm token riêng theo ngôn ngữ.
- **R8-5. Tab ngôn ngữ của form hiện mọi ngôn ngữ trong bảng `locales`, kể cả ngôn ngữ đang tắt,** theo thứ tự `sort_order`, ngôn ngữ mặc định đứng đầu. Mục đích: dịch xong mới bật. Tab của ngôn ngữ đang tắt có thêm nhãn "đang tắt".
- **R8-6. Cổng chặn khi bật một ngôn ngữ (R10 của đợt 5).** Server chỉ cho bật ngôn ngữ X khi **mọi key `email.*` gửi cho khách** có bản cho X. Bản đó có thể là hàng `content_strings` với `status='reviewed'`, hoặc bản mặc định trong registry (`registryLocaleDefault`). Thiếu bản nào thì màn liệt kê các key thiếu và dẫn link tới `/admin/content/emails?lang=X`.
  - Thiếu nội dung khác thì **không chặn** (spec §5.1: thiếu thì lấy EN). Màn chỉ cảnh báo kèm độ phủ.
- **R8-7. Chính sách theo ngôn ngữ (T8.3, SEC-3).**
  - Mỗi ngôn ngữ có chuỗi phiên bản riêng trong `legal_versions (locale, version)`. `reservations.consent_locale` ghi ngôn ngữ của chữ mà khách đã đồng ý.
  - Trang chính sách ở ngôn ngữ X in chữ của X (lùi về EN theo từng key), cùng ngày của phiên bản mới nhất của X.
    - Nếu X chưa có hàng nào trong `legal_versions`, trang dùng phiên bản EN và ghi `consent_locale = 'en'`. Lý do: khách thấy chữ EN.
  - Drawer gửi kèm phiên bản và ngôn ngữ mà nó đã render. `submitReservation` chỉ giữ cặp đó nếu hàng tương ứng tồn tại, không thì lấy phiên bản mới nhất của ngôn ngữ đó (SEC-3). Nhánh `COALESCE` giữ nguyên.
- **R8-8. Email tiếng Anh dùng `en-GB` và giờ 24h (GUX-5) (chủ dự án) [mặc định như vừa nêu].** Web khách đổi cùng lúc, để email và web in cùng một kiểu ngày. Các chuỗi ICU đã ghim trong `render.test.ts` đổi theo.
- **R8-9. Origin của site:** `siteOrigin()` lấy `SITE_URL`, rồi `https://${VERCEL_PROJECT_PRODUCTION_URL}`, rồi `http://localhost:3000`.
  - `SITE_URL` là biến mới, chỉ đặt cho Production khi có domain riêng. Không có thì Vercel tự cấp `VERCEL_PROJECT_PRODUCTION_URL`, khi "Automatically expose System Environment Variables" đang bật.
  - Preview vẫn trỏ canonical về production, để Google không index preview.
- **R8-10. Nút chuyển ngôn ngữ là link thường** (`<a href>`, tải lại cả trang; spec §6.1). Lúc bấm, nó ghi cookie `NEXT_LOCALE` (path `/`, 1 năm, `SameSite=Lax`) ở client, trước khi trình duyệt chuyển trang. Trang của ngôn ngữ đích là cùng đường dẫn sau tiền tố. Nút ẩn khi chỉ có một ngôn ngữ đang bật (spec §3).
- **R8-11. Draft Mode chỉ để xem trước ngôn ngữ đang tắt và bản dịch chưa bật.** Nó không có "nội dung nháp": spec không có bản nháp, mọi lần lưu là thật.
  - Trang ở Draft Mode hiện một dải "Đang xem trước" có nút thoát. Dải chỉ render khi `draftMode().isEnabled`. Chữ của nó là key registry `ui.preview_banner` và `ui.preview_exit`.
  - Dải có `noindex`, và không xuất hiện trong nút chuyển ngôn ngữ, sitemap hay hreflang (spec §6.1).
- **R8-12. Tìm kiếm với ngôn ngữ CJK:** `fold_search()` giữ nguyên (Latin và Việt). Với `ko`, `zh-hans` và `ja`, ô tìm so khớp chuỗi con sau `toLowerCase()`, vì các chữ đó không có dấu để bỏ. C11 có test khóa hành vi này.
- **R8-13. "Dịch từ EN" và "Dịch tất cả bằng AI" là đợt 9.** Đợt 8 không đặt chỗ cho nút "Dịch từ EN" trong `TranslatableField`. Trên `/admin/translations`, nút dịch hàng loạt hiện ở trạng thái tắt, kèm dòng "Có từ đợt 9 (AI)".

## Review Focus

- **C2:** proxy không được làm chậm hay làm hỏng redirect khi DB chết. Kiểm lại có timeout, TTL, phần cache lần lỗi, và cách lùi về `['en']`.
- **C4–C6:** một ngôn ngữ đang tắt **không bao giờ** lộ ra cho khách: không ở trang, không ở nút chuyển ngôn ngữ, sitemap hay hreflang, không ở redirect của proxy, không ở email. Ngoại lệ duy nhất là Draft Mode của nhân viên đã đăng nhập.
- **C6:** `/api/admin/preview` chỉ nhận đường dẫn tương đối bắt đầu bằng `/<mã ngôn ngữ>`, không thì thành open redirect. Route phải gọi `requirePermission` trước mọi việc khác.
- **C8 và C9:** "EN đã đổi" phải đúng hai chiều:
  - lưu EN thì mọi bản dịch đã có thành "EN đã đổi";

```sql
-- Phase 8 (spec §5.2, §8): the languages admin. Expand only, one transaction, safe to re-run.
--
-- 1. locales.script names a key of SCRIPT_FONTS (lib/i18n/scripts.ts). A

-- 2. A language a social link names in visible_locales (no FK: an array) cannot
--    be deleted (L8-6). Codes never change after creation (R8-1), so the array
--    never needs rewriting; the trigger only refuses.
-- 3. The privacy policy is versioned per language (T8.3, SEC-3, R8-7): the
--    wording a guest agreed to is (consent_locale, consent_version).

ALTER TABLE locales DROP CONSTRAINT IF EXISTS locales_script_check;
ALTER TABLE locales ADD CONSTRAINT locales_script_check
  CHECK (script IN ('latin', 'vietnamese', 'hangul', 'han-simplified', 'japanese'));

CREATE OR REPLACE FUNCTION locales_delete_guard() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  IF EXISTS (SELECT 1 FROM social_links WHERE OLD.code = ANY (visible_locales)) THEN
    RAISE EXCEPTION 'locale % is named by social_links.visible_locales', OLD.code
      USING ERRCODE = 'P0001', HINT = 'Remove the language from those links first.';
  END IF;
  RETURN OLD;
END
$$;
DROP TRIGGER IF EXISTS locales_delete_guard ON locales;
CREATE TRIGGER locales_delete_guard BEFORE DELETE ON locales
  FOR EACH ROW EXECUTE FUNCTION locales_delete_guard();

-- legal_versions: one sequence of versions per language.
ALTER TABLE legal_versions ADD COLUMN IF NOT EXISTS locale text NOT NULL DEFAULT 'en';
DO $fk$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'legal_versions_locale_fk') THEN
    ALTER TABLE legal_versions ADD CONSTRAINT legal_versions_locale_fk

END
$fk$;

DO $fk$
```

```ts
export function pickLocale(cookie: string | undefined, acceptLanguage: string | null, enabled: readonly string[]): string {
  const set = new Set(enabled.map((l) => l.toLowerCase()));
  const c = cookie?.trim().toLowerCase();
  if (c && set.has(c)) return c;
  const ranked = (acceptLanguage ?? '')
    .split(',')
    .map((part) => {
      const [tag, ...params] = part.trim().split(';');
      const q = params.map((p) => p.trim()).find((p) => p.startsWith('q='));
      const n = q ? Number(q.slice(2)) : 1;
      return { tag: tag.trim().toLowerCase(), q: Number.isFinite(n) ? Math.min(Math.max(n, 0), 1) : 0 };
    })
    .filter((x) => x.tag && x.tag !== '*' && x.q > 0)
    .sort((a, b) => b.q - a.q);
  for (const { tag } of ranked) {
    const parts = tag.split('-');
    for (let n = parts.length; n > 0; n--) {
      const candidate = parts.slice(0, n).join('-');
      if (set.has(candidate)) return candidate;
    }
  }
  return DEFAULT_LOCALE;
}
```

```ts
import 'server-only';
import { getPool } from '@/db/client';
import { FALLBACK_LOCALES } from './locales';

const TTL_MS = 60_000;
const TIMEOUT_MS = 500;
let cache: { at: number; value: readonly string[] } | null = null;

/**
 * The enabled languages for the proxy's redirect (spec §6.1): one query at most
 * every 60 s per instance, given up after 500 ms. A failure or a timeout serves
 * ['en'] and is cached like a success, so a dead database costs one slow
 * redirect per minute, not one per request. The only database read of the proxy.
 */
export async function enabledLocalesBestEffort(now = Date.now()): Promise<readonly string[]> {
  if (cache && now - cache.at < TTL_MS) return cache.value;
  let timer: ReturnType<typeof setTimeout> | undefined;
  try {
    const query = getPool().query<{ code: string }>('SELECT code FROM locales WHERE is_enabled ORDER BY sort_order, code');
    const timeout = new Promise<never>((_, reject) => {
      timer = setTimeout(() => reject(new Error('timeout')), TIMEOUT_MS);
    });
    const { rows } = await Promise.race([query, timeout]);
    cache = { at: now, value: rows.length ? rows.map((r) => r.code) : FALLBACK_LOCALES };
  } catch {
    cache = { at: now, value: FALLBACK_LOCALES };
  } finally {
    clearTimeout(timer);
  }
  return cache.value;
}

/** Tests only. */
export function resetEnabledLocalesCache(): void {
  cache = null;
}
```

```ts
import { draftMode } from 'next/headers';

import { previewTarget } from '@/lib/server/content/preview';

/** Staff open a guest page in Draft Mode (spec §6.1): a disabled language, unindexed, outside the switcher and the sitemap. */
export async function GET(request: NextRequest) {
  // The same shape as app/api/admin/emails/preview/route.ts: a refused check answers 403, never throws.
  try {
    await requirePermission({ content: ['read'] });
  } catch {
    return new Response('Forbidden', { status: 403 });
  }
  // No Origin check (unlike the email preview's POST): a top-level GET from a link carries none. Turning
  // Draft Mode on for a signed-in staff member is the only effect, and it changes no data.
  const target = await previewTarget(request.nextUrl.searchParams.get('path'));
  if (!target) return new NextResponse('Bad preview path', { status: 400 });
  (await draftMode()).enable();
  return NextResponse.redirect(new URL(target, request.nextUrl.origin), 303);
}
```

```ts
import { createHash } from 'node:crypto';

/**
 * The fingerprint of a row's default-language text when a translation was written (spec §5.1
 * source_hash). A translation is "EN đã đổi" when its source_hash differs from the default row's
 * current fingerprint. Columns in the def's order; null and '' are the same ("not set").
 */
export function sourceHash(columns: readonly string[], defaultRow: Record<string, unknown> | undefined): string {
  const values = columns.map((c) => {
    const v = defaultRow?.[c];
    return v === null || v === undefined || v === '' ? null : String(v);
  });
  return createHash('sha256').update(JSON.stringify(values)).digest('hex');
}

export type TranslationState = 'missing' | 'machine' | 'reviewed' | 'stale';

/** The state a form tab and the coverage screen show for one translation row. The default language is always 'reviewed'. */
export function translationState(row: { status: string; source_hash: string | null } | undefined, currentSource: string, isDefault: boolean): TranslationState {
  if (isDefault) return 'reviewed';
  if (!row) return 'missing';
  if (row.source_hash && row.source_hash !== currentSource) return 'stale';
  return row.status === 'machine' ? 'machine' : 'reviewed';
}
```
